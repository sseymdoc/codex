# 后台任务行为

对照本机 Claude Desktop `2.42304.2.0`，选择用户截图中的会话栏及单行任务布局，即 `claudeai_cc_epitaxy_session_presets_main` 开启的分支。Claude 的开关关闭分支仍使用旧卡片布局；本次没有把静态代码当作 Claude 的运行实测。

## 已对齐规则

| 场景 | 行为 |
| --- | --- |
| 没有运行任务 | 会话栏不显示后台任务卡片；已完成记录仍能从后台任务面板查看 |
| 新任务出现 | 卡片出现；不自动开面板，不自动展开卡片或每条任务 |
| 卡片开合 | 默认收起，按会话记忆；任务完成、消失和重新出现均不覆盖用户选择；其它卡片的既有全局偏好保留 |
| 卡片运行列表 | 按开始时间升序，未知时间排末尾；初次显示四条，显示更多展开全部；回落到四条以内或折叠卡片后重置更多状态 |
| 卡片完成入口 | 只显示完成家族计数，不把完成任务平铺在运行列表内；最后一条运行任务结束后卡片消失 |
| 点击运行行 | 打开面板、展开目标及祖先，滚动定位到目标；不停止任务 |
| 点击完成入口 | 打开面板并展开完成分区 |
| 面板家族 | 根及直接叶子作为一组；有后代的子节点提升为独立家族；父或叶子仍在运行时保留在运行区 |
| 面板排序 | 运行按开始时间升序；完成家族按最近结束时间降序，同时间保留逆序来源顺序；缺失时间不补猜测值 |
| 完成与行开合 | 完成分区默认收起；分区和行状态按会话保留，任务完成不会强行关闭原先展开的详情；每条叶子独立开合 |
| 家族子项 | 根展开同时显示自己的详情与子项；运行家族将完成、停止叶子放入内部完成折叠区；整个家族结束后直接显示全部叶子，失败优先，其余按结束时间倒序 |
| 大列表 | 完成家族先展示十组，再以一百组增加；额外保留显式展开的组和前一百个含失败的组；运行组始终可见 |
| 长标题 | 根据实际宽度单行省略，数据不按字符截掉；仅溢出时提供完整提示，会话栏提示最多四行；计时及停止按钮保留空间 |
| 窄面板 | 宽度小于 `300px` 隐藏时长；失败、停止等状态文字仍显示 |
| 完整命令 | 展开后完整显示，按宽度换行，命令块最多 `200px` 高，独立纵向滚动 |
| 输出 | 最多显示尾部 `8000` 字符并标注更早内容未显示；输出块最多 `200px` 高，独立滚动 |
| 输出跟随 | 位于底部时跟随输出、布局及字体更新；距离底部至少 `16px` 或正在选择输出文本时不抢滚动位置；运行转完成的重挂载保留暂停和滚动位置，主动收起后重置 |
| 清除 | 垃圾桶只隐藏当前完成家族，不终止运行任务、不删除后端记录；按任务的执行轮次隐藏，新一轮即使已结束也能重新出现 |
| 停止 | 运行任务有独立停止按钮；请求中显示忙碌，失败保留原状态并显示错误；完成任务没有停止按钮 |
| 关闭面板 | 只关闭展示，不停止任务；卡片再次点击仍能打开任务与历史 |
| 本地展示状态 | 最多一百个会话，每会话最多一千条展开或隐藏键；不修改后端会话历史 |

## 后台身份与原生兼容

原生 `commandExecution.processId` 在前台初次等待时已经存在。原先 `backgroundTerminals/list` 也可能包含尚未返回的前台进程，因此两者都不能单独证明“已转后台”。

自编译后端通过可选的 `backgrounded` 字段记录事实：实验型后端启用时，新命令从 `false` 开始，只有实际返回后台会话 ID 才成为 `true`，完成及历史恢复保留该值。转换使用同一命令 ID，保留此前输出和首次开始时间，不再记一次插件启动。

该字段及列表的增强语义受 `CODEX_UI_EXPERIMENTAL_BACKEND=1` 和 `Config.experimental_backend` 门控。禁用时保持原生字段与行为，普通配置、模型参数及后端路径不能自行开启。

旧记录或原生后端缺少确认标记时，不根据命令时长或进程 ID 追认后台身份。仍有实时进程但无法确认的记录显示为状态未知，不计运行卡片或完成家族。更早已结束的记录无法准确追认，本次不改写其历史。Codex 命令结束协议没有独立的已停止状态，因此 shell 停止后仍按实际完成或失败结果显示；子代理中断显示已停止。Codex 没有提供的 Claude loop/workflow 执行器与模型令牌明细也不虚构。

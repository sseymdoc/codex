# 历史会话打开后断连：Git 预览输出溢出

## 结论

`1.2.28` 的 64 MiB 保护阻止了 Electron 主进程的字符串溢出，但没有消除大回复来源。
用户指定历史会话的隔离副本在同一安装代码和原后端下重现断连，超限回复的请求编号为 `31`，方法为 `gitDiffToRemote`。
历史分页回复约 2.18 MB，两张自动读取的图片回复分别约 98 KB 和 131 KB，均未超限。

打开历史会话会自动刷新更改卡片。原生 `git-utils::diff_against_sha` 对未跟踪文件使用
`git diff --binary --no-index`，把安装包、归档等二进制内容编码为完整补丁，再塞进单条 JSON-RPC 回复。
Orchestrator 之前只在完整回复到达后补齐中文未跟踪文件，因此无法阻止这个回复先撑爆行缓冲。

隔离仓库中，一个 52 MiB 的随机二进制文件使实际使用的后端返回 71,325,158 字节的单条回复，约 68 MiB，包含 `GIT binary patch`。
此路径早于 Orchestrator 重构存在；上次修复将主进程崩溃改为显式断连，没有修复本次确认的来源。

## 修复范围

- 界面服务直接处理既有 `gitDiffToRemote` 请求，保留 `{ sha, diff }` 回复格式和远端候选比较顺序。
- 使用普通 Git 文本差异；二进制文件保留变更标记，不生成二进制补丁正文。
- 未跟踪路径使用 NUL 分隔，保留中文、空格和以短横线开头的文件；移除原来的补齐逻辑，避免重复读取。
- 每条 Git 输出及合计预览限制为 8 MiB。超限返回该请求的错误，并在更改面板显示原因，不返回不完整差异，不断开会话。
- 保留 Git 的 5 秒超时、禁用外部 diff/textconv 和安全配置；连接关闭、后端退出和服务退出时取消预览。
- 不修改 Rust、后端包、历史数据、工作树文件或忽略规则；原生与实验后端使用同一界面保护。

## 验证

| 检查 | 结果 |
| --- | --- |
| 修复前实际安装代码 + 指定历史副本 | 重现 64 MiB 提示；输入框消失；请求来源为 `gitDiffToRemote` |
| 修复后桌面代码 + 同一历史副本 | 历史和输入框正常；无 fatal 或超限后端回复；当前大型仓库在更改面板返回独立的文本预览限制 |
| 52 MiB 二进制回归 | 只返回变更标记；中文未跟踪文件保留；后续普通 RPC 可用 |
| 预览预算、远端比较基准、取消、非法参数 | 通过；文本超限后连接仍可用 |
| HTTP/SSE 集成、权限与后端开关 | 通过 |
| 浏览器 CLI 与 Vite 入口 | 二进制预览、RPC、服务关闭及后端进程退出均通过 |
| 完整 Node 测试 | 366/366 通过，无跳过 |
| 类型检查及前端构建 | 通过；保留现有的 bundle 体积提示 |

现场副本与对照证据保存在 `.tmp/history-overflow-20261024/`，其中包含
`git-repro.json`、`electron-history-before.json`、`electron-history-after.json` 和 `tests.log`。
这些文件不纳入发布包。测试使用隔离配置，不向真实会话发送消息，不复制凭据，不安装或替换正在运行的应用。

## 边界

此修复解决界面自动 Git 预览造成的断连；其他协议消息仍受原有 64 MiB 保护。
超过 8 MiB 的文本差异需要使用外部 Git 工具查看。隔离副本验证不等于用户安装后的人工复验。
